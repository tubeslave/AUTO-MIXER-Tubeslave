# Голосовой помощник → мониторные шины музыкантов (директива оператора 2026-07-30)

Оператор: экранная индикация вторична (frontend-опция); основной канал —
ГОЛОС в мониторинг музыкантов. Русский и английский, выбор языка во
frontend. Система при подключении сканирует шины мониторинга (обычно
«IEM»/in-ear, «MON»/monitor или имя музыканта) и произносит требования в
эти шины: «Система ждёт бас-бочку» и т.д.

## Архитектура

1. **TTS-движок (зона Claude).** Этап 1 — прототип на macOS `say`
   (голоса Milena/Милена RU, Samantha EN; нулевые зависимости, есть
   сегодня). Этап 2 — Piper TTS (MIT, onnxruntime, offline, CPU
   real-time; голоса ru_RU irina/dmitri/ruslan, en_US множество) — БЕЗ
   torch (PyTorch-ветка проекта мертва, Piper её не воскрешает).
   Кэш фраз: стандартные реплики рендерятся заранее в WAV 48к.
2. **Фразовый движок (Claude).** Источник событий уже существует:
   on_channel_update per-channel саундчека (waiting_for_signal / signal /
   skipped / timeout / repeat). Шаблоны фраз ru/en на инструмент:
   «Ждём бас-бочку» / "Kick, please", «Спасибо. Следующий — малый»,
   «Канал пропущен», + свободные реплики оператора текстом из frontend.
3. **Сканер мониторных шин (Claude).** По подключении: перечислить шины,
   прочитать имена ($name по OSC), классифицировать паттернами
   (IEM|EAR|MON|MONITOR|WEDGE + имена музыкантов ru/en из состава),
   confidence на каждую; маппинг «музыкант→шина» показать оператору во
   frontend на ПОДТВЕРЖДЕНИЕ — без подтверждённого маппинга голос не
   шлётся никуда.
4. **Тракт голоса (Claude + Codex).** Mac проигрывает TTS в возвратный
   канал WING USB (карта 48x48 двунаправленная) или Dante-передачу (Ф9);
   на пульте возвратный канал маршрутизируется в подтверждённые
   мониторные шины. Уровень жёстко ограничен (талкбэк-кап ~−20 dBFS,
   фейд-ин, лимитер в тракте рендера фразы), никогда полная шкала — это
   уши музыкантов в in-ear.
5. **Safety (Codex, класс A).** Новая write-family «talkback_routing»:
   назначение/снятие возвратного канала на мониторные шины = live-записи
   → allowlist/промоут по установленной дисциплине, авто-ревёрт
   маршрутизации по завершении саундчека, полный readback. Голос активен
   ТОЛЬКО в режиме SOUNDCHECK (режимная лента), в SHOW — запрещён
   намертво. Никаких записей до операторской разблокировки — до неё
   прототип играет в локальный выход Mac (оператор слышит сам).
6. **Frontend (Kimi).** Выбор языка ru/en, вкл/выкл голоса, редактор
   маппинга музыкант→шина (с confidence сканера), журнал произнесённых
   фраз, поле свободной реплики.

## Порядок

Этап 0 (быстрый прототип): фразовый движок + macOS say → локальный выход,
события per-channel. Этап 1: сканер шин + UI маппинга. Этап 2: Piper,
кэш фраз, уровневый кап. Этап 3 (после разблокировки live-записей +
DEC-0009 Dante): маршрутизация в мониторы на пульте, полевые ворота —
саундчек, где музыканты слышат помощника в ушах.

Связки: per-channel mode (уже в ветке), Ф8 (пер-инструментный проход =
сбор identity-паспортов — голос объявляет и ведёт этот проход), Ф9
(Dante-тракт как боевой транспорт голоса), voice_command_* (ASR-вход
оператора — встречное направление, уже в server).
