# Proposal: WING Read-Only Preflight Handoff Prestart Command Field

## Short thesis

The operator handoff packet should expose and validate the exact prestart no-WING check command at the top level, not only inside nested commands.

## What I understood

The current MVP cannot move to supervised fader/gain proof until a real WING read-only preflight artifact is captured and reviewed. Offline work can still reduce operator error around that first blocker by making the handoff packet harder to misread or tamper with.

## Proposed solution

- Add `backend_port_prestart_check_command` to the top-level handoff packet.
- Render that field in the markdown safety boundary.
- Make `tools/no_wing_release_check.py` validate the top-level command against `backend/wing_readonly_preflight_contract.py`.
- Add positive and negative tests for the new field.

## Likely files to touch

- `tools/build_wing_readonly_preflight_handoff_packet.py`
- `tools/no_wing_release_check.py`
- `tests/test_wing_readonly_preflight_handoff_packet.py`
- `tests/test_no_wing_release_check.py`
- `Docs/adr/wing-readonly-preflight-handoff-prestart-command-field-20260611.md`
- `Docs/reports/AUTOMIXER_WING_READONLY_PREFLIGHT_HANDOFF_PRESTART_COMMAND_FIELD_20260611.md`

## Alternatives considered

- Leave the command only inside `commands.prestart_backend_port_check`: rejected because the top-level safety boundary should be self-contained.
- Add a new prestart artifact hash requirement: rejected for this slice because it changes the hardware runbook workflow more broadly.

## Risks

Older handoff packet fixtures without the top-level field will fail no-WING artifact validation until regenerated. This is acceptable because the packet is generated by repo tooling and contains no live authority.

## Test plan

- Focused handoff/no-WING tests.
- Adjacent WING preflight/no-WING stack.
- Full backend suite before commit if focused validation passes.

## Where the other agent may disagree

Kimi may prefer making the top-level field the only source of truth and deriving nested commands from it. This slice keeps both fields and validates equality through the shared contract, which is lower risk.
