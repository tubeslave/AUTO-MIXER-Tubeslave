# Codex Proposal: WING MVP Evidence SHA Format Gate

## Short thesis

Read-only evidence intake should reject malformed digest strings before a
candidate can be treated as valid evidence.

## What I understood

The active blocker remains `WING read-only connection proof`. Prior slices
added SHA format checks for accepted-candidate prestart traces and no-WING plan
artifacts. The evidence validator still treated non-empty
`expected_plan_sha256` and `backend_port_prestart_summary_sha256` as
structurally present, which is weaker than the shared contract.

## Proposed solution

Reuse `is_sha256_hexdigest()` from `backend/wing_readonly_preflight_contract.py`
inside `backend/wing_readonly_preflight_evidence.py`. Add regression coverage
for malformed expected-plan and prestart-summary digests on inline/candidate
payloads.

## Likely files to touch

- `backend/wing_readonly_preflight_evidence.py`
- `tests/test_wing_readonly_preflight_evidence.py`
- Council/report docs for this slice.

## Alternatives considered

- Rely only on file SHA mismatch checks. Rejected because not all validation
  entrypoints have a file path available at the first artifact-intake boundary.
- Duplicate the regex locally. Rejected because the shared contract already
  exposes the canonical helper.

## Risks

Old hand-authored fixtures with placeholder digest strings will now fail. That
is intended; readiness evidence should use real lowercase SHA-256 hexdigests.

## Test plan

- Focused evidence tests.
- Full no-WING release-check module.
- Project Director rails, py_compile, memory lint, and `git diff --check`.

## Where the other agent may disagree

Kimi may prefer accepting uppercase SHA-256 strings. The existing artifacts are
generated by `hashlib.hexdigest()`, so strict lowercase keeps evidence
consistent with the rest of the WING preflight contract.
