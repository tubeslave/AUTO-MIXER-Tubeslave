# /learn — извлечение паттернов сессии

Проанализируй текущую сессию и извлеки паттерны, которые сэкономят время в будущих сессиях.

## Что искать

1. **Повторяемые баги** — ошибка, её корневая причина, что исправило. Особенно: DSP-инверсии,
   порядок аргументов, сериализация, thread safety, протокольные особенности WING/dLive.
2. **Протокольные факты** — поведение OSC/MIDI, подтверждённое на реальном железе
   (индексация, тайминги, троттлинг, особенности метров/тапов).
3. **Workarounds** — обходы ограничений библиотек, Dante/SoundGrid, WING firmware.
4. **Коррекции оператора** — когда оператор поправил подход: зафиксировать «как надо» и почему.

## Что НЕ извлекать

- Опечатки и одноразовые синтаксические ошибки
- Разовые сбои внешних API
- То, что уже записано в CLAUDE.md или выводится из кода

## Куда сохранять

| Тип паттерна | Место |
|---|---|
| Баг/правило кода, DSP, протокол | CLAUDE.md → «Зафиксированные правила» (соответствующий подраздел) |
| Правило, проверяемое статически (regex по коду) | Предложить также добавить проверку в `.claude/hooks/py_safety_check.py` |
| Архитектурное решение | CLAUDE.md → «Архитектурные решения» |
| Проверенное правило микширования | `.claude/evals/` через `/eval` (пайплайн проб на WING) |

## Процесс

1. Просмотри сессию, выбери 1–3 самых ценных паттерна
2. Для каждого сформулируй одну строку в стиле существующих правил CLAUDE.md:
   конкретика, что ломается при нарушении, как правильно
3. Покажи оператору черновик правок ДО записи
4. После подтверждения — внеси в CLAUDE.md (и в hook-скрипт, если проверка автоматизируема)

Формат строки правила — как в CLAUDE.md: `паттерн/API` — суть бага, правильный вариант,
чем грозит нарушение. Одна строка — одно правило.
