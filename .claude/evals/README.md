# Эвалы AUTO-MIXER

Хранилище eval-определений и логов прогонов. Управляется командой `/eval`.

```
.claude/evals/
  <имя>.md    — определение эвала (до реализации)
  <имя>.log   — история прогонов (дата, результат, кто грейдер)
```

## Шаблон определения

```markdown
## EVAL: <имя>
Создан: <дата>
Тип: dsp | mixing-rule

### Capability
- [ ] <проверяемый критерий с ожидаемым числом/порогом>
- [ ] ...

### Regression
- [ ] существующие tests/ проходят (команда: PYTHONPATH=backend python -m pytest tests/ -x -q)
- [ ] <safety-путь, который нельзя сломать>

### Грейдер
- dsp: pytest на синтетических сигналах (детерминированный)
- mixing-rule: вердикт оператора на реальном WING (пайплайн: кандидат → проба → вердикт → счёт)

### Критерии приёмки
- capability: pass@3 > 90%
- regression (safety-пути): pass^3 = 100%
```

## Шаблон строки лога

```
2026-07-26 | check | capability 3/4 | regression 2/2 | grader: pytest | заметки
2026-07-27 | probe | kick ch1 eq.tonal_target | вердикт оператора: принято | заметки
```

## Примеры capability-критериев (DSP)

- Синус 997 Hz, -20 dBFS, 48 kHz → интегральный LUFS = -23.0 ± 0.1 LU (BS.1770-4)
- Сигнал с задержкой +5 мс относительно reference → gcc_phat возвращает +5 мс (знак!)
- True peak intersample-пика синуса 11.025 kHz оценён с 4x oversampling, ошибка < 0.3 dB
- Gate с hysteresis 3 dB: сигнал в коридоре гистерезиса НЕ вызывает повторное срабатывание

Правила: эвалы определяются до кода; safety-пути — pass^k без исключений;
слуховые вердикты не заменяются моделью.
