# ADR: WING read-only plan-output write errors deny expected-plan readiness

## Context

The real WING read-only preflight requires an expected-plan JSON generated by
`--plan-only`. If `--plan-only --plan-output` cannot write that file, no usable
expected-plan artifact exists.

## Options considered

1. Report only `plan_output_write_error`.
2. Also mark the expected-plan surface as not matched.

## Decision

Use option 2. Plan-output write-error stops now include
`expected_plan_match: false` and
`expected_plan_violations: ["plan_output_write_error"]`.

## Why this won

The blocked stdout JSON may be copied into review tooling even when the file was
not written. It must be unambiguous that this is not a valid expected-plan
artifact for a real backend/WING run.

## Rejected alternatives

Relying on `status: blocked` was too indirect compared with other expected-plan
failure paths, which expose a stable violation list.

## Implementation plan

Add expected-plan denial fields to the plan-output write-error block and assert
them in the regression.

## Test plan

Run the targeted plan-output write-error test, focused WING/no-WING suite,
no-WING quick, `git diff --check`, and the standard pytest gate.

## Risks and rollback

Risk is minimal because this only adds false/violation fields on an already
blocked plan-only path. Rollback is to remove the fields and assertions.
