## 1. Консенсус — чем проект ЯВЛЯЕТСЯ и каким должен быть

Единогласно: скелет правильный, «ритуалы доверия» (gated executor с
pre-read/readback/rollback/демоутом, live_apply dry-run→confirm→panic,
абсолютные Ayaic-цели) — это и есть продукт. Но сегодня система — «ассистент
саундчека под присмотром», а не автомикшер для концертов: цепь защиты от
заводки мертва, true peak врёт на ВЧ, паника стоит в общей очереди троттла.
Диагноз безопасности: **инверсия fail-closed в fail-deaf** — система идеально
не делает ничего ровно в том сценарии, где бездействие и есть вред.
Формула целевой модели: **fail-closed для эстетики, fail-active для защиты**.
Формула измерений: **K1 решает → K2/K3 подтверждают → K5 судит → K6 (оператор)
благословляет** (контуры — в WORKING_ALGORITHM.md §1).

## 2. Плюсы (сохранить как фундамент)

- Gated executor — эталон; менять не нужно, аварийный контур строить НА нём.
- live_apply: dry-run default → confirm → readback → panic — скелет доверия.
- balance_v3: абсолютные цели, анти-храповик — урок 2026-07-03 усвоен системно.
- Кросс-адаптивные v3-прогоны одним батчем ДО поканального цикла; bleed-заморозка до коррекций.
- Bleed-proximity guard, ring-тест resonance_eq, identity-core в маскинге.
- Дисциплина протокольных фактов WING (pre-trim, троттл, thr26, 0/1-base, слоты FX).
- Lease-механика и append-only аудит Codex-процесса.

## 3. Минусы (дисквалифицирующие и системные)

- Мёртвая цепь подавления заводки + детектор слеп к установившейся/дрейфующей
  заводке + алерты не доходят до UI. Единственный сценарий, ради которого
  оператор согласится на автономию, — не работает.
- TruePeakMeter LPF 12 кГц; auto_eq срез→буст; ceiling только на input-каналах;
  троттл head-of-line; default −144 при пустом кэше.
- До шести писателей одного фейдера за прогон; фазовая стадия после тональных;
  сильный фазовый решатель (phase_v3) не в default-пути; gate-порог не следует
  за тримом; метрология судьи K5 (мастер-петли) искажена.
- Процессный слой растёт быстрее продукта: 94 contract-модуля, STATE.json
  276 КБ, 8.3 ГБ артефактов в git, 407 тестовых файлов плоско; значимая доля
  «зелёного» проверяет процесс, а не математику.
- UI — инженерные табы, а не пульт оператора шоу (нет режимной ленты,
  алерт-центра, ленты решений, blessed mix, паники).
- Неосвоенная поверхность пульта: headamp (настоящий преамп), mute-группы,
  W-Live (виртуальный саундчек), RTA-метры, user-кнопки; `/snap/store` —
  неофициальный адрес, вероятный тихий no-op.

## 5. Матрица автономии (семейство × режим; L0 observe / L1 propose / L2 supervised / L3 autonomous)

| Семейство | Саундчек | Концерт | Emergency-канал |
|---|---|---|---|
| trim/gain | L3 (bounded, абсолют; boost opt-in) | **L1** (Р2) | — |
| ch-fader | L3 | L2 «круиз» opt-in | privileged dip |
| bus/dca-fader, mute-группы | L2→L3 | L2 | privileged mute |
| hpf, gate | L3 | L1 | — |
| tonal EQ, comp, pan, FX | L2→L3 | **L1 навсегда** | — |
| feedback notch | L3 | L3 (цель) | privileged |
| master fader | L1 | L1 | L2, только вниз |
| mute канала, phase/pol, 48V, snapshot GO, altsw, headamp | L2 (с подтверждением) | L1/никогда | никогда |

Промоут любого семейства — только proof-пакетом через леджер Codex
(dry-run → supervised на железе → N чистых прогонов → строка в RUN_LEDGER),
авто-демоут по инциденту; для emergency-класса демоут per-target с cooldown,
не глобальный по типу.

## 6. Решения по пульту WING (эксперт + совет)

Приоритет освоения новой поверхности: (1) mute-группы `/mgrp/1..8/mute` +
DCA-сцены + user-кнопка/GPIO как аппаратная паника — дёшево, безопасно,
сильно; (2) blessed-mix-ритуал + interlock «snapshot GO / `/io/altsw` только
вне live»; (3) headamp `/io/in/<grp>/<n>/g` — только после proof-раннера,
шаги ≤3 дБ, только саундчек, `vph` (фантом) НЕ ПИСАТЬ НИКОГДА; (4) RTA-метры
(токен 0xaa) — консольный спектр для feedback-детекции без аудиозахвата;
(5) W-Live виртуальный саундчек — v1.5. Список из 10 экспериментов на железе —
в MASTER_PLAN_TO_V1.md §«Программа изучения пульта».

## 7. Критерии «полностью рабочей версии» (acceptance, зафиксировано)

1. Feedback end-to-end на реальном PA: подавление ≤ 500 мс от порога детекции,
   ≥95% на ≥20 индукциях, 0 ложных на корпусе аккордеон/орган/вокал; алерт в
   UI ≤ 200 мс.
2. True peak: BS.1770-4 тест-векторы ±0.3 дБ до 20 кГц.
3. Property-тест ceiling: ни один write-путь (WING и dLive, все поверхности)
   не может превысить потолок.
4. Паника STOP AI / REVERT < 200 мс при искусственно забитой очереди троттла.
5. Kill-тест: смерть backend в APPLYING → консистентный пульт, рестарт без
   слепых записей.
6. Соук 2 часа: ноль дрейфа (сумма |Δ| ограничена), ноль потерянных rollback.
7. Каждая запись трассируема из UI ≤ 2 тапа.
8. Знаковые баги закрыты числовыми тестами на синтетике.
9. 3 супервизируемых концерта подряд без вмешательства оператора по
   безопасности. До этого слово «автономный» не употребляем.
10. Мёртвый код в attic; README-запуск работает без torch.
