# Алгоритм работы AUTO-MIXER (as-is и целевой)

Зафиксирован советом трёх ассистентов 2026-07-29 (протокол: `COUNCIL_2026-07-29.md`).
Цель документа — единое понимание того, КАК проект работает сейчас и как должен
работать в рабочей версии (v1) в режимах саундчека и концерта.

## 1. Физические измерительные контуры (данность железа)

| # | Контур | Что видит | Тип |
|---|---|---|---|
| K1 | Pre-trim USB-тапы каналов | Сырой источник ДО trim/gate/EQ/comp/fader/inv/dly | open-loop вход |
| K2 | OSC readback (active GET + /xremote для fader/mute) | Управляющие величины пульта | closed-loop по параметрам |
| K3 | WING-метры (бинарный протокол, post-trim) | Уровень после трима | closed-loop по уровню |
| K4 | Пост-фейдерные USB-тапы/стемы | Уровень после фейдера | opt-in (роутинг оператора) |
| K5 | Мастер-петля Main LR → USB 47/48 (post-mute, PRE-limiter) | Всю применённую обработку | полный closed-loop |
| K6 | Оператор | Полярность суммы, преамп, зал | внешний контур |

**Главный закон:** тип контура диктует закон управления. Open-loop (K1) —
только однократные АБСОЛЮТНЫЕ цели (итерация по слепому замеру = интеграторный
храповик, live-провал 2026-07-03). Closed-loop (K3/K5) — итерация допустима,
но к абсолютной цели, с демпфированием и лимитом проходов.
Формула: **K1 решает → K2/K3 подтверждают → K5 судит → K6 благословляет.**

## 2. Алгоритм as-is (текущая реализация)

```
server.py (WS :8765) → handlers/ → AutoSoundcheckEngine
  IDLE → DISCOVERING (поиск/подключение пульта, скан каналов, классификация
         по имени channel_recognizer) → MEASURING (захват K1, WING-метры)
       → ANALYZING (SignalAnalyzer ≥3 с; v3-прогоны одним кросс-адаптивным
         батчем: balance_v3/eq_v3/comp_v3/pan_v3; bleed-заморозка ДО прогонов)
       → APPLYING (типизированные actions → GatedCorrectionActionExecutor:
         промоут-гейт → pre-read → SafetyController (политика состояния →
         bounds → rate-limit → транслятор) → WingClient (ceiling → троттл)
         → OSC-readback 0.25 дБ → авто-rollback при расхождении → демоут)
       → RUNNING (_monitor_loop 10 Гц: feedback-детекция, новые каналы,
         autofoh-анализ — всё в одном потоке под одним локом)
Живые записи по умолчанию: только ChannelGainMove / ChannelFaderMove.
Остальное — proposal-only в операторскую очередь (live_apply: dry-run →
confirm → readback → rollback; panic stop).
Мастер-оценка: master_mix_eval по K5 (честный NO_SIGNAL при мьюте).
```

Известные системные дефекты as-is (ревью 2026-07-29): контур подавления
заводки мёртв (политика/транслятор/промоут); до шести писателей одного
фейдера за прогон; фазовая стадия стоит ПОСЛЕ тональных; default-путь фазы
использует legacy-замер с фиктивной когерентностью вместо phase_v3;
gate-порог не следует за тримом (comp следует); метрология K5 искажена
(mono-downmix LUFS, TruePeak LPF 12 кГц); тихий fallback v3 → legacy.

## 3. Целевой алгоритм v1 (решение совета)

### 3.1. Саундчек — порядок стадий и критерии остановки

```
0. Prep       connect → скан → снапшот-бэкап → классификация (подтверждение
              оператором, ~30 с) → корреляционная проба USB-маппинга −42 dBFS
              → проверка silence_fallback → исключения зафиксированы ДО
              коррекций (bleed-frozen, master-reference, стереопары).
              Стоп: снапшот полон, K2 отвечает, капчур живой.
1. Linecheck  (пошаговый, по одному каналу): наличие сигнала, gain staging
              по K3 (конвергенция: медиана 3 проходов, коридор ±1.5 LU),
              санити полярности пар. Трим-boost только по opt-in.
              Стоп: коридор ИЛИ «трим исчерпан — нужен преамп» (residual).
2. Gate       сразу после трима; порог trim-компенсирован; bleed-каналы —
              только гейт. Стоп: readback OK.
3. Phase/pol  ДО тональных стадий (когерентная сумма — предпосылка честного
              баланса): onset-gated GCC-PHAT (phase_v3), MAD ≤ 0.5 мс,
              same-source ≤ 2 мс, полярность по r после выравнивания на лаг.
              Один писатель delay. Стоп: критерии ИЛИ residual «соло-проход».
4. EQ         HPF → resonance (ring-тест для срезов >3 дБ) → erb-masking
              (вне тембрового ядра) → spectral caps. A/B-вердикт по K5.
              Стоп: полосы readback-верифицированы, eq/on=1, K5 не ухудшен.
5. Comp       GR-цель из K1-огибающей, порог в консольном домене (+Δtrim),
              makeup bounded (GR + TP headroom). Стоп: readback thr/thr26 OK.
6. Balance    per-channel (balance_v3, Ayaic-плоскости) → stem/bus → DCA;
              стерео-идентичность — constraint решателя, не пост-фикс.
              ОДИН владелец фейдера за прогон. Стоп: residual ≤ 1 LU.
7. FX         opt-in: preins-preflight, премиум-модели только слоты 1–8,
              readback модели ≠ NONE. Стоп: операторский review.
8. Master     единственная законно итеративная стадия: K5, абсолютные цели,
              лимит проходов, anti-oscillation. TP цель −8 dBTP (PRE-limiter).
9. Blessed mix — оператор явно утверждает микс кнопкой: снапшот-точка
              возврата для концерта. Без него в режим SHOW не попасть.
```

### 3.2. Концерт (режим SHOW) — асимметрия автономии

Автономны ТОЛЬКО защитные действия («fail-closed для эстетики, fail-active
для защиты»):
- **Аварийный контур заводки** (привилегированный канал мимо матрицы
  уместности, но через полный gated-цикл): ступень 1 — notch −3..−6 дБ
  (бюджет ≤2/канал, ≤4 активных, TTL 120 с с реальным ревёртом); ступень 2 —
  fader-dip канала −3 дБ hold с авто-восстановлением +1 дБ/2 с; master —
  только вниз, только EMERGENCY_SPL, пол −6 дБ.
- True-peak реакция и live-monitor алерты (≤200 мс до UI).
- Bounded «круиз» баланса — строго opt-in: ≤ ±1.5 дБ от blessed mix.
Всё остальное (тональный EQ, comp, pan, FX, трим, mute) — proposal-only.
Автотрим в концерте — никогда (gain тянет мониторные миксы).

Паника (две кнопки, всегда видимы, аварийная полоса мимо троттла, <200 мс):
**STOP AI** (заморозка записей) и **REVERT** (bounded-рампа к blessed mix,
НЕ мьют мастера).

### 3.3. Лестница автономии (per семейство × режим)

L0 observe → L1 propose → L2 supervised → L3 autonomous (бюджеты + TTL +
авто-демоут по инциденту). Промоут семейства — только через proof-пакет
(dry-run → supervised на железе → N чистых прогонов → строка в леджере
Codex), никогда руками в конфиге. Матрица целевых уровней — в протоколе
совещания `COUNCIL_2026-07-29.md`, §«Матрица автономии».

## 4. Инварианты (не отменяются ничем, живут на транспортной границе)

1. Fader ceiling ≤ 0 dBFS на ВСЕХ фейдерных поверхностях обоих клиентов
   (ch/bus/dca/main/fx_return/sends; WING и dLive).
2. Каждый write-метод возвращает bool из send().
3. current неизвестен → не писать (никаких дефолтов −144).
4. True peak < −1.0 dBTP перед любым повышением gain (метр — честный, 4x OS
   до 24 кГц).
5. Троттл не задерживает аварийную полосу (приоритет emergency > operator >
   correction, trailing-edge коалесценция).
6. Загрузка снапшота/reset/полярность/трим-в-концерте — двухшаговое
   подтверждение оператора.
7. Каждая запись трассируема: намерение → записано → readback → (rollback).
