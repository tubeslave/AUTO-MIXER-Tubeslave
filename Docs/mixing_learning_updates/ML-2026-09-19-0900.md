## Sources actually read

### S-ML-20260919-0900-01 — RelFx

- **Title:** *Beyond Dry References: Learning Relative Audio Effects Representations via Contrastive Distance Learning*.
- **Publication date:** 2026-08-11; discovered 2026-09-19.
- **Stable ID:** arXiv `2608.10573v1`; DOI `10.48550/arXiv.2608.10573`.
- **Full text:** [arXiv HTML](https://arxiv.org/html/2608.10573); [abstract record](https://arxiv.org/abs/2608.10573).
- **License:** CC BY 4.0 for the paper.
- **Reading depth:** full methods, training data, effect chain, evaluation, all main results, ablations, bidirectional properties, limitations and ethics statement.

RelFx encodes the transformation represented by an ordered pair rather than the absolute effect state of one signal. During training, reference and processed-side material are adjacent, non-overlapping 10-second clips from the same structural section; neither must be dry. The dual-branch model uses a log-mel frontend, shared CNN14 backbone, cross-attention, differential gating and a 128-dimensional embedding. Training covers eight sequential effects — EQ, distortion, multiband compression, gain, stereo imaging, limiting, delay and reverb — with 72 continuous parameters and eight activation switches.

Under the paper's MUSDB18 inference-time-optimization protocol, the best non-oracle RelFx configuration reached average median multi-resolution STFT loss `1.388`, versus `1.601` for Fx-Encoder++. The MoisesDB-only version reached `1.449`. These numbers support the representation under that protocol; they do not show musical preference.

The ablations are more useful than the headline metric:

1. Removing cross-attention slightly improved transfer loss (`1.399 → 1.392`) while reducing retrieval, so cross-attention is not essential to the main endpoint.
2. Removing cross-segment sampling improved retrieval R@1 (`67.3 → 69.6`) but degraded transfer loss (`1.399 → 1.876`, about 34%). The model otherwise learns content shortcuts.
3. Removing parameter regression or dynamic effect-probability scheduling also improved retrieval while worsening transfer.

Therefore retrieval and effect-transfer quality are distinct validation targets. Neither is a substitute for signal-safety checks or a controlled listening test.

The bidirectional variant produced approximately sign-reversed embeddings when the input order was swapped (`cos ≈ -0.998`) and partial compositional behavior (`cos ≈ 0.842`). This is useful structure for candidate relative editing, not evidence that a reverse processor chain or perceptually exact undo operation exists.

Explicit limits: no controlled listening test, no full dense-rock evaluation, no source-specific effect separation within mixtures, and no test of unseen chain orders or real production chains. The internal licensed training collection and large training compute are not available for independent project reproduction.

### S-ML-20260917-0900-03 — WildFX, updated from the queue

- **Title:** *WildFX: A DAW-Powered Pipeline for In-the-Wild Audio FX Graph Modeling*.
- **Proceedings:** DAFx-26; discovered 2026-09-17; fully reviewed 2026-09-19.
- **Full text:** [DAFx PDF](https://dafx.de/paper-archive/2026/papers/DAFx26_paper_56.pdf); [official record](https://dafx.de/paper-archive/details/Wa0iqrebqJulEpXKIftRMA).
- **License:** CC BY 4.0 for the paper.
- **Reading depth:** full eight pages, including schema, renderer, compatibility comparison, dataset, graph-estimation experiment, results and limitations.

WildFX drives REAPER in a Dockerized Linux environment and records input stems, plugins, parameters, channel counts, main/control edges, linear gains, sidechains and output paths. It supports VST/VST3/LV2/CLAP plus bridged Windows plugins, but the reported comparison covers 96 public Linux VST3 plugins only.

The compatibility table reports: pedalboard loaded 56/96; DawDreamer had 74 fully working, three loaded-but-silent, 17 failures and one crash among 95; WildFX loaded 96/96. This establishes broader loading compatibility for the checked inventory. It does **not** establish correct full-song rendering, parameter-state fidelity, latency, tails, gain, absence of clipping, or listening quality. The test used loading checks and, for DawDreamer, isolated one-second renders at 44.1 kHz with a 512-sample buffer.

WildFX represents supported projects as constrained acyclic graphs. Layered scheduling respects dependencies, but the system does not claim unrestricted DAW routing and does not quantify speedup over simpler project-level parallelism. The paper's blind graph estimator used a five-plugin inventory, a 30k-step budget and one training run per setting; node error rates stayed high. This is initial data-pipeline validation, not a certificate of production graph recovery.

The headless limitation is especially important: REAPER exposes no built-in error reporting or inspection for this path, so the authors manually validated each pipeline step in a GUI before deployment. Our candidate gate therefore requires rendered-signal checks, not only schema validity or plugin load.

## Candidate rules

All remain `auto_apply:false`.

1. Test a relative ordered-pair target against the existing absolute target only when source role and section are matched; cancel on content leakage or worse blind preference. Confidence: medium.
2. Pair relative references inside one structural section; the paper's 10-second window is study-specific and not a project preset. Confidence: medium-high.
3. Report retrieval, transfer fit, signal safety and blind preference separately. Confidence: high.
4. Do not apply a mixture-level relative target to source-specific processors until stem/role attribution is resolved. Confidence: high.
5. Admit a plugin to automation only after finite, non-silent, level-bounded and deterministic renders, not after load success alone. Confidence: high.
6. Persist exact processor order, main/control edges, channels, gains, parameter state and plugin version. Confidence: high.
7. Before trusting layered rendering, null-test it against an equivalent direct in-DAW graph, including sidechains and tails. Confidence: medium-high.
8. Do not integrate research code or demo assets without an explicit compatible license, fixed revision, asset rights and an offline no-upload path. Confidence: high.
