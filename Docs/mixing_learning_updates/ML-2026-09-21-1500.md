## Literature and implementation sources actually read

### SRC-ML-20260921-1500-01 — BSRNN replication version family

- Fresh version: [Investigating the performance and energy costs of replicating Band-Split RNN for Music Source Separation](https://arxiv.org/html/2609.21918), arXiv `2609.21918`, DOI `10.48550/arXiv.2609.21918`, submitted 2026-09-18.
- Canonical longer version: [The Costs of Reproducibility in Music Separation Research: a Replication of Band-Split RNN](https://arxiv.org/html/2603.09187), arXiv `2603.09187`, DOI `10.48550/arXiv.2603.09187`, submitted 2026-03-10.
- Reading depth: `2609.21918 = full_text_complete`; `2603.09187 = abstract_method_architecture_selected_sections`.
- Deduplication: the shared authors, experiment lineage, repository and overlapping results make these one version family. They are not two independent replications.
- Retained result: the reproduced base model reached average cSDR `7.42` versus `8.24` reported for the original; alternative data raised it to `7.87`. The short paper reports that increasing early-stopping patience from 10 to 30 added roughly `0.2 dB` while increasing energy by `54%`.
- Variance matters: the small-model trials varied by about `0.3 dB` for vocals and `0.1 dB` on average. Deltas of that order are not convincing from one seed.
- A 4096-sample STFT window with 1024 hop degraded average cSDR to about `6.6`; the authors link the drum loss to reduced time resolution. This is a task-specific training observation, not an EQ or transient preset.
- Limits: MUSDB18-HQ only, no controlled listening, no mix-utility test, no phase/mono/true-peak/onset safety gates, mostly single-seed reporting, and project energy is hardware/workflow-specific. The reported `24.2 MWh` project total includes failed or complementary work and cannot be treated as the cost of one clean replication.

### AUD-ML-20260921-1500-01 — BSRNN repository

- Repository: [magronp/bsrnn](https://github.com/magronp/bsrnn), revision `41e9ce4e796159c7a6e6287d4d198ec1cedbf0ce`; licence: MIT for repository code; execution: `false`.
- The README associates the project with arXiv `2603.09187` and additionally reports optimized oBSRNN/oBSRNN-SIMO results that the new short version does not contain. Full parity therefore requires the longer version and exact configuration.
- The repository warns that its faster cSDR path differs from `museval` because silent frames become `NaN`; headline values from the two implementations are not interchangeable without a metric contract.
- `seed=42` is configured, but deterministic execution is disabled. The public path does not establish bitwise or multi-run reproducibility.
- Missing checkpoints may initialise random weights according to the evaluation documentation. Integration must fail closed rather than silently render random pseudo-stems.
- Inference offers overlapping segmentation/stitching, but the repository search found no automated tests for sum consistency, target/non-target leakage, true peak, loudness, phase/mono, boundaries, latency or tails. No code or model was run.

### SRC-ML-20260921-1500-02 — Internet Archive Music Dataset

- Primary text: [The Internet Archive Music Dataset](https://arxiv.org/pdf/2609.20870), arXiv `2609.20870`, DOI `10.48550/arXiv.2609.20870`, ISMIR 2026.
- Official repository: [bvm810/IAMD](https://github.com/bvm810/IAMD), revision `779a8596d18638ca4c0340f24b5da0f00526201d`.
- Reading depth: `full_text_complete` plus repository documentation and rights audit; execution: `false`.
- Corpus: the paper describes about `4.1M` non-overlapping 30-second segments and `34.8k` hours from `548k` Internet Archive files; the current repository describes `4.25M` clips. This is version drift, not an independent count.
- Rights design: files with uploader-declared CC licences are selected and ND material is excluded because the pipeline re-encodes audio. However, the authors explicitly warn that uploader metadata can be inaccurate. MusicBrainz/ISWC matching flags likely copyrighted cases but is heuristic, not file-level clearance.
- Deduplication is filename/duration based within an item, not acoustic fingerprinting. It can miss the same recording under different names and can merge or retain wrong cases.
- Captions combine an audio captioner, Archive metadata, tag models and an LLM. They are machine-generated and not human-verified.
- The subjective study used 100 samples and 20 volunteers, with each item rated twice, and evaluates caption correctness/completeness—not production quality, reference suitability or mix similarity.
- Dataset scope: complete mixes in lossy MP3, not raw→processed stems→final-mix packages. Per-sample licences include CC0/BY/BY-SA and several NC variants; repository MIT applies to authored code, not the audio. IAMD remains `catalog_candidate / rights_verification_required`.

## Knowledge Cards added

1. `KC-ML-20260921-1500-01`: same-author retitled arXiv submissions with one repository and overlapping experiments form one version family, not independent confirmation.
2. `KC-ML-20260921-1500-02`: a replication gap must be reported against an exact metric implementation, split, checkpoint and configuration.

7. `KC-ML-20260921-1500-07`: missing-checkpoint fallback to random weights is a safety failure unless inference stops before rendering.
8. `KC-ML-20260921-1500-08`: separator pseudo-stems require sum-consistency, leakage, boundary, transient, phase/mono and peak tests before mix use.
9. `KC-ML-20260921-1500-09`: an uploader-declared Creative Commons field is evidence to inspect, not proof that the uploader controlled every right.
