## Source Card updates

### `SRC-ML-20260928-0900-01` — Real-Time Music Source Separation on a Low-Power Audio DSP

- **Stable ID / source:** `arXiv:2609.12201v1` — https://arxiv.org/abs/2609.12201
- **Reading depth:** complete five-page paper reread; method, tables, figures, deployment path, streaming ablation, metric definitions and limitations.
- **Evidence coverage:** block-wise metrics use all 50 MUSDB18-HQ test songs. The failure trajectory in Fig. 3(b) is the median and IQR of only eight tracks, with the headline stable value taken over the last 30 seconds. This is enough to reveal a real failure mode but not to estimate its prevalence on arbitrary project material.
- **Single-factor ablation:** the paper states that the two checkpoints in the streaming comparison differ only in training context; both are streamed with recurrent state and convolution cache carried. That makes the collapse evidence more useful than a generic architecture comparison.
- **Deployment margin:** the reported full-band build uses 10.44 ms worst case inside an 11.6 ms hop, leaving about 1.16 ms timing margin; 1963/2040 kB L2 leaves 77 kB and 447/512 kB L1 leaves 65 kB. These margins are target- and build-specific and do not include an Automixer callback graph, OSC/control work, other channels or host contention.
- **Precision boundary:** convolution ring caches use float16 while weights and indefinitely carried GRU state stay float32. The paper reports close tracking to a PyTorch streaming twin and hours without drift, but does not publish the runtime, profiler, checkpoint, test manifest or independent reproduction.
- **Artifact status:** the paper says the profiler, feasibility script and on-device reference runtime *will be released*. No exact repository is linked on the arXiv record. `artifact_available:false` remains the correct status.
- **Limited conclusion:** continuous frame-by-frame parity, exact cache semantics and measured target-host worst case are mandatory gates. The reported embedded timing is not a transferable latency promise for the Mac or Wing environment.

### `SRC-ML-20260928-0900-02` — Room Impulse Response Embeddings for Speech Enhancement in Noisy and Reverberant Environments

- **Stable ID / source:** `arXiv:2609.31041v1` — https://arxiv.org/abs/2609.31041
- **Status/date:** ICASSP 2027 submission, 25 September 2026; preprint.
- **Reading depth:** complete five-page paper: three-stage representation learning, datasets, room-parameter probes, t-SNE/silhouette view, FiLM conditioning, metrics, results and limitations.
- **Method:** a 10-layer, 256-hidden-unit, four-head Conformer produces a global 256-dimensional normalized embedding from four-second, 16 kHz single-channel speech. Stage 1 learns RIR identity contrastively on reverberant speech; stage 2 continues with noisy-reverberant speech; stage 3 distils the clean-reverberant teacher embedding into the noisy-reverberant student. The noise-pair sampling probability `p=0.7` is a paper choice, not a mixing parameter.
- **Training/evaluation domain:** 100 hours of EARS speech, EARS-Reverb/EARS-WHAMR, WHAM noise at `-2.5…17.5 dB` SNR, then additional CHiME-3/SINS/SMS-WSJ noise. Test degradations use the EARS test split with unseen measured BUT-ReverbDB RIRs and DEMAND noise at `0…20 dB` SNR. This is useful room/noise separation evidence, but still synthetic convolution of speech and not rock multitrack bleed.
- **Representation probe:** under noisy-reverberant testing, stage 3 improves DRR prediction from stage 2's `3.66 dB / rho=0.38` to `2.56 dB / rho=0.51`; T60 is `0.23 s / rho=0.68`. The t-SNE display uses one RIR per each of nine rooms and reports silhouette `0.21`, so it supports partial room structure, not exact RIR recovery or causal invariance.
- **Enhancement result:** adding FiLM conditioning after each decoder block improves STOI, CD, SRMR, DNSMOS and both reported WER columns relative to the corresponding unconditioned DFN3/two-step model. However, for the weak ASR, raw-input WER is `36.85` versus `39.52/38.81` for the conditioned reverberant systems, and `63.47` versus `67.81/64.61` for noisy-reverberant systems. The strong ASR does improve, most notably `41.32` to `35.15` for noisy-reverberant two-step+FiLM.
- **Design limits:** no confidence intervals, significance tests, multi-seed variance, listening test, matched-capacity side-information control, real-time cost of the encoder/FiLM path, music test, multichannel test or frame-wise/dynamic-room evaluation are reported. The authors explicitly leave multichannel and frame-wise representations to future work.
- **Limited conclusion:** room-conditioned processing is a plausible research direction, but the present evidence only supports fixed/global conditioning for synthetic single-channel speech. Do not infer that an RIR embedding can directly control live drum gating, bleed removal, room level or creative reverb.

### `EXP-ML-20260928-1200-02` — measured host-margin stress test

- **Baseline A:** separator callback alone on the intended Mac/embedded target.
- **Variant B:** identical separator inside the complete Automixer callback graph; surrounding graph load is the only factor.
- **Controls:** checkpoint, block/hop, sample rate, precision, channel count, power mode, buffer, I/O and test stream.
- **Measure:** mean/p95/p99.9/max callback time, xruns, memory high-water mark, thermal drift, CPU scheduling jitter and output null against the standalone build.
- **Listening:** only if raw outputs differ; then separate loudness-matched randomized copies.
- **Protect:** deadline margin, sample accuracy, continuity, monitoring latency and headroom.
- **Cancel:** target build or profiler is unavailable, or another processing setting changes.

### `EXP-ML-20260928-1200-03` — RIR identity versus matched shuffled conditioning

- **Baseline A:** the same trained FiLM-conditioned enhancer receives a batch-permuted embedding with matched distribution.
- **Variant B:** it receives the correct utterance/RIR embedding; correspondence is the only factor.
- **Controls:** one checkpoint, identical waveform, FiLM path, embedding scale, latency, precision and render gain.
- **Material:** first reproduce on rights-clear speech; only then use licensed vocal/drum-room stems convolved with held-out measured RIRs plus held-out noise/bleed.
- **Measure:** speech metrics only in the speech stage; for music add transient/onset error, decay/EDR, pitch/formant stability, stereo correlation, mono residual, sample/true peak and section-conditioned blind preference. Preserve raw renders; use separate BS.1770-matched listening copies.
- **Protect:** attacks, pitch, phase, room character, noise floor and headroom.
- **Success:** correct identity consistently beats shuffled identity without musical damage.
- **Cancel:** the effect wins only by level, room/noise families overlap training, or the exact encoder/enhancer checkpoint is unavailable.

### `EXP-ML-20260928-1200-04` — global embedding under a room transition

- **Baseline A:** fixed embedding from the first acoustic condition.
- **Variant B:** embedding refreshed on a fixed four-second cadence; refresh is the only factor.
- **Controls:** same enhancer, RIR pair, transition time, source, noise, gain, state and render path.
- **Measure:** pre/post-transition metric trajectory, recovery time, gain/pan/phase discontinuity, tail truncation, onset error, stereo/mono and sample/true peak; blind rating on loudness-matched randomized copies.
- **Protect:** transition continuity, natural decay, attacks, localisation and headroom.
- **Success:** refresh improves the post-change region without an audible boundary artifact.
- **Cancel:** the published global encoder cannot be run deterministically or any enhancement parameter besides the embedding changes.
