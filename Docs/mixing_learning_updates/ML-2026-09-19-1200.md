## Result

The full RelFx paper was re-read at equation, evaluation-protocol and ablation level; the substantive method, experiment, listening-study and limitation sections of ST-ITO were read as the closest independent primary comparator. The WildFX paper was cross-checked against the current public tests and rendering code at revision `061e204e`.

The main correction is material: the RelFx configuration producing the headline `1.388` average multi-resolution STFT loss is not a purely relative representation. Its base fusion explicitly mixes the differential term with the absolute processed-signal embedding. The published ablation removes the entire reference branch, but does not isolate “pure differential” versus “hybrid differential + absolute” fusion. The result therefore supports the complete dual-input system under its benchmark, not the stronger claim that relative distance alone caused the gain.

A second qualification concerns model selection. Each sample receives seven optimization restarts, and the reported restart is selected by the lowest ground-truth multi-resolution STFT loss. This is a valid oracle-assisted benchmark comparison when applied consistently, but that selector is unavailable in normal reference mixing, where the exact processed target for the source is unknown. A deployable evaluation must select by an available objective and report its regret relative to oracle reranking.

The WildFX audit also became more precise. The current repository contains meaningful safety tests beyond plugin loading: it rejects non-finite final renders, preserves float output, checks deterministic fixture preparation and runs REAPER integration cases for simple chains, sidechains and splitters. Those checks are useful, but an RMS activity threshold does not establish graph equivalence, and the fixed default three-second tail is not a universal decay-completion criterion.

## Sources actually read

### S-ML-20260919-0900-01 — RelFx, deep-review update

- **Stable ID:** arXiv `2608.10573v1`; DOI `10.48550/arXiv.2608.10573`.
- **Full text:** [arXiv HTML](https://arxiv.org/html/2608.10573).
- **Reading depth:** complete methods, equations, training construction, evaluation protocol, result tables, ablations, bidirectional tests, limitations and ethics statement; re-read specifically for causal attribution and deployability.

The best non-oracle result (`RelFx Standard`, average median `L_d=1.388`) uses the base fusion

`g ⊙ (e_proc − e_ref) + (1 − g) ⊙ e_proc`.

It therefore retains an explicit absolute processed-signal term. The separately trained bidirectional variant removes that term and reaches `1.389`, numerically close, but the paper provides no uncertainty interval or paired significance test establishing equivalence. The single-branch ablation (`1.457`) changes several things at once: it removes the reference branch, pair interaction and relative comparison. It does not isolate the absolute term inside the base fusion.

The reported sign reversal (`cos≈−0.998`) is mostly an architectural constraint: order-invariant gating, a difference term and odd `tanh` projection are designed to produce antisymmetry. It verifies that the constraint survives the learned projection; it is not evidence that the underlying processor chain is invertible or that subtracting the embedding performs dereverberation, unclipping or distortion removal. Composition remains approximate (`cos≈0.842`) and was checked only on 100 drum and 100 vocal triplets.

The evaluation uses 100 samples per instrument, seven Adam restarts, up to 200 iterations and ground-truth `L_d` to retain the best restart. This keeps the published comparison internally useful, but creates an oracle-selection gap for deployment. The paper reports medians by instrument without confidence intervals, song-level dispersion or a controlled listening test.

The “dry-reference-free” claim applies to representation training. The evaluation still uses Fx-Normalization to match the Fx-Encoder++ protocol and optimizes a known differentiable chain on synthetic/controlled targets. Unseen production chains, unknown topology, mixture attribution and dense-rock preference remain unresolved.

### S-ML-20260919-1200-01 — ST-ITO comparator

- **Title:** *ST-ITO: Controlling Audio Effects for Style Transfer with Inference-Time Optimization*.
- **Stable ID:** arXiv `2410.21233v1`; DOI `10.48550/arXiv.2410.21233`.
- **Full text:** [arXiv HTML](https://arxiv.org/html/2410.21233).
- **Reading depth:** full substantive method, training, benchmark, objective and subjective results, discussion and limitations.

ST-ITO is not an independent replication of RelFx, but it is a useful independent check on the inference “better effect metric → better production result.” Its authors explicitly note that optimizing their learned similarity alone does not permit strong style-transfer conclusions. Their 23-participant listening study found simple rule-based processing competitive or better for simple filter styles, while differences between optimized and learned baselines were not clear in every case. They also report a failure mode for guitar-tone matching and require the user to supply an appropriate chain.

This supports a bounded project conclusion: an effect-aware embedding may guide search, but the final gate must include a deployable selector, signal integrity and loudness-matched listening. ST-ITO does not validate RelFx numerically and is not counted as independent confirmation of RelFx's benchmark advantage.

Positive evidence in the current revision:

1. final export rejects non-finite samples and removes partial output;
2. float waveform precision and weighted mixing are tested;
3. deterministic fixture/preset preparation is tested;
4. sidechain and splitter graphs have explicit integration cases;
5. a REAPER integration output must have the expected rate/length and non-trivial RMS activity;
6. silent or non-finite candidates are rejected during preset clustering.

Remaining gaps:

1. RMS activity proves neither correct parameters nor equivalence to a direct in-DAW graph;
2. no published/current test null-compares layered and direct execution sample-for-sample;
3. there is no explicit true-peak, loudness, latency-compensation or state-recall acceptance test;
4. `delay`, `echo` and `reverb` receive a default three-second tail, but actual decay completion is not measured;
5. preset clustering peak-normalizes and converts to mono before MFCC/KMeans selection, so loudness and stereo differences are intentionally removed from that selection stage;
6. repository licensing remains unspecified, blocking integration despite readable source.
