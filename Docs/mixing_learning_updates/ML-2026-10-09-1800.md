## Outcome

The scientific conclusion is unchanged: DPNMM is research on environment-conditioned final playback, not evidence for multitrack de-masking. The artifact assessment is materially downgraded. The public repository at commit `6fb3516e50ec1de0f70d4c4e36a7d88a62e74a97` is syntactically readable, but its documented entry points do not form a self-consistent runnable package.

Static AST checks confirmed four call-contract failures: the training script passes two unsupported HPSS keywords to its dataloader; the evaluation dataloader requires the same two arguments but the evaluator omits them; the inference example calls its own four-argument `main` with only three arguments; and the shared configuration lacks the `data`/`mode` fields later read by training or the model wrapper. The loaders also discard the sample rates returned by `torchaudio.load`, so arbitrary inputs are not resampled or rejected against the declared 44.1 kHz contract.

The deeper DSP audit also changes how the published numeric limits must be read. The model clamps each Bark control to `+10/3` and `-5/3 dB`, with the last two controls forced to zero, but overlapping interpolation patterns are summed before conversion to a linear filter. A deterministic re-expression of the public formulas at 44.1 kHz/2048 samples gives a possible all-positive realised response up to approximately `+12.33 dB` and all-negative response down to approximately `-6.16 dB` at some bins. These are static code implications, not measured audio results or safe presets.

Likewise, the wrapper labels attack and release smoothing as 250 ms but computes `gamma = N/(tau*sr)` with `N=2048`, while the STFT hop at 75% overlap is 512 samples. Under the visible one-pole recurrence this corresponds to an approximate 56.5 ms e-fold time, not 250 ms. The intended versus effective smoothing contract must be resolved before any listening test.

## Knowledge Cards

### KC-ML-20261009-1800-01 — syntax validity is not runnable reproducibility

A repository can parse successfully while its public training, evaluation and inference entry points disagree on arguments and configuration fields. Reproducibility requires a pinned smoke test that reaches model construction and one deterministic forward pass, not only readable source. Confidence: `high_static_contract_audit`.

### KC-ML-20261009-1800-02 — Bark-control limits are not necessarily realised filter limits

When overlapping band patterns are summed, limits on individual Bark controls do not directly bound every FFT-bin gain. Record both control values and the realised frequency response; never copy the control clamp as a production EQ ceiling. Confidence: `high_source_code_plus_static_derivation`.

### KC-ML-20261009-1800-03 — smoothing constants require the actual update interval

A time constant is meaningful only with the recurrence and update interval. Here, 250 ms labels coexist with a recurrence coefficient based on the 2048-sample window while updates occur every 512 samples. The effective response must be measured or analytically reconciled before transfer. Confidence: `high_source_code_plus_static_derivation`.

### KC-ML-20261009-1800-04 — input sample-rate validation is part of the model contract

Using a 44.1 kHz psychoacoustic/STFT configuration while silently accepting a file at another rate changes the physical frequencies represented by every band. A safe wrapper must resample explicitly or reject mismatched inputs and record the decision. Confidence: `high_source_code`.

### KC-ML-20261009-1800-05 — DPNMM GLD is not project loudness matching

The paper artifact's 100 ms A-weighted GLD is useful for its playback-level objective but cannot replace BS.1770 matching, true-peak checks or blinded musical judgement in a project A/B. Confidence: `high_metric_boundary`.
