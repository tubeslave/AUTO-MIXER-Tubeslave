### SRC-ML-20261006-1800-01 — ViSQOL v3

- title: *ViSQOL v3: An Open Source Production Ready Objective Speech and Audio Metric*
- stable IDs: arXiv `2004.09584`; QoMEX 2020
- authors: Michael Chinen, Felicia S. C. Lim, Jan Skoglund, Nikita Gureev, Feargus O'Gorman, Andrew Hines
- full text: https://arxiv.org/pdf/2004.09584
- official implementation: https://github.com/google/visqol
- status: `studied_full_text_peer_reviewed_dependency`
- reading depth: complete six-page paper plus official README usage/interpretation guidance

ViSQOL is full-reference. It aligns reference and degraded audio, forms gammatone spectrogram patches, computes NSIM and maps similarity to MOS; audio mode uses an SVR. The paper states that the audio SVR training sets covered bitrates down to 24 kb/s, while very-low-rate 6–18 kb/s behavior was out of distribution and could violate monotonicity. It recommends checking each use case with other evidence rather than treating absolute MOS as universally meaningful.

The current official README adds an operational contract: audio mode expects 48 kHz and downmixes multichannel input to mono; the reference should be clean and at least as good as the degraded signal; active excerpts should be roughly 8–10 seconds; single scores are not meaningful and treatments should be aggregated across several samples. These requirements make ViSQOL unsuitable as a stereo-image endpoint and unsuitable for arbitrary commercial-reference matching.

Confidence: high for the algorithm and documented input contract; medium for transfer to the planned bandlimit check; low for direct mix-quality acceptance.

## Knowledge Cards

1. `KC-ML-20261006-1800-01` — Metric independence is a provenance property. A second metric is not independent if it supplied labels, features, calibration data or selection targets to the first.
2. `KC-ML-20261006-1800-02` — DeePAQ's human listening-test evaluation is external to its ViSQOL-derived training target; the evaluation is informative even though DeePAQ–ViSQOL agreement is dependent.
3. `KC-ML-20261006-1800-03` — A 2f score is not implementation-agnostic: record the PEAQ implementation, matching coefficient set and 0–100 clamp.
4. `KC-ML-20261006-1800-04` — ViSQOL audio mode downmixes to mono, so stereo width, correlation and spatial regressions require separate diagnostics/listening.
5. `KC-ML-20261006-1800-05` — ViSQOL single scores should not drive acceptance; aggregate same-treatment results over several active excerpts and report dispersion.
6. `KC-ML-20261006-1800-06` — An objective metric's front end may generalize while its learned mapping fails out of distribution; declare both the representation and calibration domain.
