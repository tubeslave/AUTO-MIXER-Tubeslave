## Outcome

The PAEDB code audit narrows an earlier conclusion: exact additivity is broken by the 128-sample fade only in the default Torch branch; the NumPy branch does not apply that fade. The public splitter still operates on individual WAV files rather than song groups. Repeating its exact shuffle/slice logic on a structural 385-song × five-file manifest with `80/10/10` places 260 of 385 song families in more than one partition. This is a code-derived risk demonstration, not a claim about an unreleased actual manifest. The repository also has an invalid README example (`--type elae` is not an accepted CLI choice), conflicting example/default ratios (`80/10/10` versus `90/10/0`), no namespace in output names, and no released manifest, training code, weights or listener data.

The full thesis resolves one gap but leaves another. It reports Nemenyi post-hoc tests: Mel-RoFormer and ELAE are not significantly different on envelopment, spatial/temporal quality or spectral quality (`p=.965`, `.979`, `.995`). That is failure to detect a difference, not an equivalence or non-inferiority test. The claimed `264` observations remain irreconcilable with 12 participants × six excerpts × four systems × three criteria (`864` scalar ratings); `264 = 11×6×4`, but neither the thesis nor paper reports excluding a participant or collapsing the three criteria that way. The objective test processes the same 12 songs through both learned systems but analyzes them with a one-way ANOVA with residual `df=22`, treating the 24 system-song values as independent rather than paired by song.

SEND's objective comparison has an additional causal limitation. Its DSP baseline selects the top `x%` frames where `x%` is the active-frame rate produced by SEND on the same test material. The comparator budget is therefore coupled to the proposed model's test output rather than frozen on validation. The listening paper also uses overlapping 95% intervals to describe SEND as comparable to the human reference; overlap is not an equivalence test, and the paper does not identify the reported `p<.01` procedure, multiplicity control or analysis unit. Human-authored trajectories still confound the SEND and CRNN conditions.

## Artifact audit

### `ART-ML-20260926-1500-02` — PAEDB repository (updated)

- **Repository:** <https://github.com/nick7ong/paedb>
- **Pinned commit:** [`d9b1386`](https://github.com/nick7ong/paedb/commit/d9b1386b2adb9a156d2884e40a5ad907cb13d547)
- **Licence:** MIT for code only; source audio remains separately restricted
- **Depth:** full static audit plus code-derived split and fade simulations; no model or audio execution

`split_dataset()` seeds Python random at 42, shuffles individual WAV paths, and slices them. With five files per song, the theoretical independent-assignment probability that a song crosses an `80/10/10` split is `1-(.8^5+.1^5+.1^5)=0.6723`. An exact structural simulation using 385 contiguous five-file families and the repository algorithm produced 260 crossing families (`67.53%`). Because the real file manifest and enumeration order are unavailable, this is a reproducible risk demonstration, not the actual PAEDB overlap count.

The Torch path saves the unfaded mixture, computes `primary=input-ambience`, then applies the same linear fade separately to primary and ambience. For the first 128 samples, the residual is exactly `mixture-(primary+ambience)=(1-fade)·mixture` before encoding; the first sample retains the full mixture in the null. The NumPy branch does not call this fade, so the defect must be scoped by implementation path. Both branches add unseeded tiny random noise internally; no generated manifest records random state.

Additional reproducibility defects:

- README calls `--type elae`, while argparse accepts only `torch_elae` and `numpy_elae`.
- README demonstrates `80/10/10`; the CLI default is `90/10/0`.
- output keys use only normalized song-directory and stem names, without source-dataset namespace or collision detection.
- the repository contains no training/evaluation code, weights, listener data, output checksums or released split manifest.
- exact Hugging Face repository IDs tested through the Hub connector were not found; broad model/dataset search was unavailable, so no Hub artifact is claimed accessible.

- **Still unresolved:** `264` cannot be reconciled with the described factorial protocol and no exclusion/missingness rule is disclosed.
- **New statistical risk:** the objective comparison ignores within-song pairing.
- **New SEND risk:** the DSP baseline's test-time movement budget is derived from SEND's test output.
- **Claim narrowed:** overlapping confidence intervals do not prove SEND is human-equivalent.
- **Reproducibility:** public PAEDB README/defaults/CLI disagree and output naming can collide across source datasets.

## Knowledge cards

1. Dataset splits must group all stems and mixtures from a song before shuffling.
2. A 385×5 structural simulation of PAEDB's public `80/10/10` logic produced 260 cross-partition song families; it is a risk audit, not the unreleased actual split.
3. PAEDB's README split ratio, CLI default and accepted algorithm name are mutually inconsistent.
4. PAEDB Torch output violates the additive null for 128 samples; the NumPy branch does not share that fade defect.
5. Additive residual from the Torch fade is analytically `(1-fade)·mixture`, not random numerical noise.
6. Output identifiers need source-dataset namespaces and collision checks.
7. Non-significant pairwise differences are not evidence of equivalence.
8. PAEDB's 264-observation count remains unexplained even in the full thesis.
9. Repeated systems on the same songs require paired or mixed-effects analysis, not independent one-way ANOVA.
10. A comparator threshold derived from the proposed model's test output couples the baseline to the proposal.
11. Overlapping 95% confidence intervals do not establish human equivalence or non-inferiority.
12. Human-authored trajectories and undisclosed subjective statistics keep SEND as an opt-in window proposer only.
