## Fully read source update

### `S-ML-20260917-0900-02` — ADAC / compiling differentiable audio graphs

Read the complete four-page [DAFx-26 demo paper](https://dafx.de/paper-archive/2026/papers/DAFx26_demo_61.pdf), the current [ADAC repository](https://github.com/cucuwritescode/adac) at commit [`6045856b`](https://github.com/cucuwritescode/adac/commit/6045856b214ed22e14c1b8342312a709d50dc47a), its MIT licence, README, code-generation paths and relevant tests. Code was inspected, not executed.

Supported conclusions:

- The compiler lowers a FLAMO/PyTorch graph into a JSON intermediate representation and emits FAUST for series, parallel and recursive composition with delays, gains/matrices and SOS filters. Its evaluated case is an LTI feedback-delay network; an SDN is reported as a larger example.
- For integer-delay evaluated graphs, full input/output impulse responses, direct paths and absolute arrival times matched the source within roughly `7e-5` of peak without alignment. The paper reports 201 unit tests and end-to-end integration tests.
- The stability analysis is a sufficient small-gain bound over emitted single-precision coefficients plus recursive-filter pole checks. A verdict of `not-certified` or `indeterminate` is not proof of instability; overriding the export guard is a conscious loss of assurance.
- Raw jointly optimised parameters are not safe user controls. The demonstrated RT60, dry/wet and pre-delay macro-controls are bounded semantic layers; the reported RT60 calibration belongs to this FDN construction, not to arbitrary processors.
- CPU and reload figures are hardware/version facts, not general guarantees: the paper reports Apple M2 results at 48 kHz, while the current README now says reloads take about 100 ms rather than the paper's under-10-ms figure.

Version boundary discovered:

- The paper rounds fractional delays to the nearest sample, bounding each line's timing error by `1/(2 fs)`. The current repository instead preserves fractional values and emits FAUST `de.fdelay` with linear interpolation. Unit code-generation tests exist for this path, but the paper's integer-delay equivalence result does not validate the newer fractional-delay implementation. A pinned-version fractional IR test is required.

Limits:

- Equivalence and stability arguments are explicitly tied to LTI processing. Nonlinear/time-varying support is future work.
- No listening test, rock mix, nonlinear processor, host matrix or broad hardware benchmark is reported.
- Transfer-function equivalence, certificate result, CPU/latency and listener preference remain separate outcomes.

### `S-ML-20260917-0900-04` — explicit Fulltone OCD v2 model

Read the complete eight-page [DAFx-26 paper](https://dafx.de/paper-archive/2026/papers/DAFx26_paper_24.pdf) and inspected the [companion repository](https://github.com/polimi-ispl/fulltoneocd) at commit [`fb5325ce`](https://github.com/polimi-ispl/fulltoneocd/commit/fb5325ceb5d2b942c5c56fd6989aafb17f06368d). The paper is CC BY 4.0; the repository contains MATLAB sources and a packaged installer but no explicit repository licence file, so reuse/integration remains blocked. Code was not run and the installer was not executed.

Supported conclusions:

- MOSFETs and a germanium diode in the asymmetric clipping stage are grouped into one equivalent nonlinear element and approximated with a canonical piecewise-linear function, avoiding the runtime iterative solver.
- Against MathWorks Simscape, the reported 1-second, 1 kHz, 1 V, 96 kHz test gave time-domain NMSE `2.2e-3` and log-spectral distance `0.56` for the explicit model. These numbers describe one illustrated operating point, not full knob/input coverage.
- On an Apple M1 Pro in MATLAB, reported real-time ratios were `3.12` for the implicit model and `0.14` for the explicit model: about 22× faster and approximately 7× real time under that test.
- The paper explicitly notes residual approximation error and proposes antiderivative antialiasing as further work. Therefore the model is not established as alias-free.

Limits and revised strength:

- Validation uses synthetic tones and a circuit simulator, not measured hardware sweeps across units, tolerances and controls.
- Listening evidence is described only as informal; there is no controlled, blind or loudness-matched test and no rock full-mix evaluation.
- Circuit-output agreement, alias control, playability, mix fit and preference must not be collapsed into one claim.
- The numerical values above are source implementation facts, not recommended distortion or mix presets.

## New knowledge and bounded rule candidates

Added **2 upgraded Source Cards**, **2 Code Cards**, **10 Knowledge Cards**, **7 rule candidates** and **4 experiment plans**. Added Video Source Cards: **0**; Reference Cards: **0**.

All rules are `auto_apply:false`:

1. Pin compiler/repository commit, operator inventory, sample rate and numeric precision before claiming source/target equivalence.
2. For an LTI compiled graph, compare the complete MIMO impulse response without alignment, including direct paths and absolute timing; a magnitude plot alone is insufficient.
3. Interpret ADAC's small-gain certificate as sufficient-only. Do not map `not-certified` or `indeterminate` to either proven stable or proven unstable, and do not silently override the production guard.
4. Do not transfer LTI guarantees to compression, clipping, envelope followers or modulation without separate nonlinear/time-varying proofs and tests.
5. Expose bounded semantic macro-controls rather than raw jointly optimised coefficients; validate the entire control range.
6. For nonlinear pedal models, evaluate circuit fidelity, aliasing, runtime and loudness-matched preference separately.
7. Do not integrate the OCD companion code while its repository licence is unresolved and local reproduction has not passed.
