## Result

One genuinely new and highly relevant source was found and fully read: StemFX, an accepted ISMIR 2026 preprint on variable-length, per-stem FX-chain prediction. Its current public implementation and the companion MultiAFx renderer were statically audited at fixed revisions. Two DAFx-26 sources were added to the deep-review queue at accurately limited reading depths: selected sections of the FDN Sandbox demo paper and the abstract/introduction of the nonlinear shimmer-reverb paper.

The useful new principle is bounded: choosing processor topology before parameter tuning can be better than forcing every target through one universal chain. StemFX reports the strongest spectral fit and the highest mean similarity rating among its compared systems. This is not a universal automatic-mixing rule. Training uses source-separated FMA pseudo-stems, cross-song combinations and random chains; separation artifacts are not quantified, musical coherence is intentionally broken, and only four broad stems are represented. The listening table reports means from 20 production-experienced listeners, but no confidence intervals, paired significance test or song-level dispersion.

The implementation audit adds two safety qualifications. The evaluation script peak-scales a summed mix when it exceeds `0.95` before computing its main metric and also reports an explicitly peak-normalized metric; neither path is suitable for detecting raw gain or clipping failures. MultiAFx tests shape, finite samples and dtype across parameter extremes, but not latency, tail completion, true peak, loudness, phase, semantic parameter equivalence or perceptual quality. An empty MultiAFx chain clips to `[-1,1]`, so it is not an unconditional identity operator.

## Sources actually read

### S-ML-20260919-1500-01 — StemFX

- **Title:** *StemFX: Learning Mixing Style Representations via Autoregressive FX Chain Prediction on Source-Separated Stems*.
- **Publication status:** accepted ISMIR 2026 preprint; published on arXiv 2026-07-17; discovered 2026-09-19.
- **Stable ID:** arXiv `2607.15634`; DOI `10.48550/arXiv.2607.15634`.
- **Full text:** [arXiv HTML](https://arxiv.org/html/2607.15634); [abstract record](https://arxiv.org/abs/2607.15634).
- **Reading depth:** complete methods, tokenization, training construction, retrieval and transfer protocols, tables, ablations, listening-test description, limitations and references.

StemFX takes paired sets of four stereo stems (`vocals`, `bass`, `drums`, `other`) and predicts a variable-length FX chain for each stem. Its 358-token vocabulary includes 85 effect names, 164 parameter names and 101 quantized value bins. The encoder uses per-band CNNs plus hand-crafted dynamics, spectral, stereo, relative-loudness and masking descriptors; a six-layer Transformer decoder emits the chain and parameters.

Training uses SCNet-separated pseudo-stems from about 105,000 FMA songs. Stems are mixed across songs to reduce content shortcuts, then each receives 1–10 random effects. The paper explicitly acknowledges that cross-song mixtures can be harmonically or rhythmically incoherent, that separation artifacts are unquantified, and that random chains do not model genre-dependent engineering practice.

The matched retrieval ablation is useful evidence for representation learning: with the same BSFiLM architecture and Sep-Aug data, autoregressive chain prediction reached `86.8%` Top-1 at eight effects versus `77.8%` for contrastive training. This endpoint is retrieval among 500 candidates, not mix preference.

For paired style transfer, StemFX reports `1.44` MRSTFT and a mean MUSHRA-style similarity score of `60.6`, compared with `54.9` for the FX-normalized low anchor. The test used 20 listeners with music-production experience. The paper does not report confidence intervals, paired significance, listener/song random effects or song-level dispersion. Fixed-chain baselines are also structurally disadvantaged: all must control a 15-device universal chain containing effects that many targets do not use, while free StemFX can omit processors. The result supports topology selection within this protocol, but does not isolate whether the gain comes from topology, training distribution, decoder capacity or renderer behavior.

The evaluation selects a balanced ten-second window in which every broad stem contributes at least 10% of total RMS energy. Quiet, sparse or role-changing sections are therefore underrepresented. Four broad separated stems are not equivalent to real session tracks such as kick/snare/toms/overheads, doubled guitars, backing vocals or effect returns.

### CODE-ML-20260919-1500-01 — StemFX implementation audit

- **Repository:** [barry-mir/stemfx](https://github.com/barry-mir/stemfx), revision [`4d7c1b14`](https://github.com/barry-mir/stemfx/commit/4d7c1b145ced902a77d28d3f390b553378ded8ad).
- **License:** MIT for repository code; paper CC BY 4.0.
- **Reading depth:** README, package metadata, current public API tests, style-transfer evaluation script and latest-commit description.
- **Executed:** no.

The repository now contains installable inference code and declares model weights and a source-separation checkpoint download path, but those remote assets and their model cards were not fetched or executed in this run. Public API tests are skipped unless a real checkpoint is supplied through `STEMFX_TEST_CKPT`; they validate shapes and chain structure, not audio safety or paper-number reproduction.

The style-transfer script sums stems and scales the mix to a peak of `0.95` whenever the sum exceeds that value. It then computes both this already conditioned MRSTFT and a separately peak-normalized MRSTFT. Raw overload, gain staging and true-peak behavior therefore need a separate unmodified render path. The script also reports simple mean/std summaries, while the paper's listener table does not expose paired uncertainty.

### CODE-ML-20260919-1500-02 — MultiAFx implementation audit

- **Repository:** [barry-mir/multiafx](https://github.com/barry-mir/multiafx), revision [`4377caab`](https://github.com/barry-mir/multiafx/commit/4377caab6dbf172cb60de366ef8a3a1e671571f4).
- **License:** MIT for repository code.
- **Reading depth:** README, package metadata, registry/extreme-parameter tests and chain tests.
- **Executed:** no.

MultiAFx provides 85 effects through seven Python libraries. Its tests run each wrapper at minimum, midpoint and maximum declared parameters, require finite `float32` output and exercise mono/stereo handling and serialization. This is useful wrapper coverage, not cross-backend acoustic equivalence. There are no explicit tests for true peak, loudness preservation, latency, tail length, state continuity, phase, no-op transparency or subjective quality. The documented empty chain clips samples to `[-1,1]`; an empty chain must therefore not be used as an unchanged control unless the input is already proven in range.

## Dataset and rights note

StemFX uses FMA mixtures, not raw professional multitracks. The [FMA project](https://github.com/mdeff/fma) says its audio is distributed under licenses chosen by individual artists and that the dataset is intended for research. Consequently, FMA is not added as a reusable rock-multitrack Reference Card. 2. Report chain retrieval, rendered signal integrity, target similarity and blind preference as separate endpoints. Confidence: high.
3. Gate any pseudo-stem-driven rule on separator/version, stem leakage, role confidence and section activity. Confidence: high.

6. Preserve an untouched raw render for peak/true-peak and gain checks; create a separate loudness-matched copy only for listening. Confidence: high.
7. Require an empty chain to null against the input within declared floating-point tolerance; cancel on clipping, gain or channel changes. Confidence: high.
