# Сквозное офлайн-сведение: два реальных набора

Дата: 2026-09-23. Исходный HEAD: `6b388bf78`.

Продолжен следующий шаг из recovery-диагностики: проверен полный канонический
`tools/repa_song_soundcheck_pipeline.py`, включая санитарную подготовку,
рендер, SmartDSP sidecar, паспорта источников и выдачу JSON-манифеста.
Предыдущий цикл является прогрессом: коммит и воспроизводимая DSP-регрессия.
В этом цикле добавлена проверка на реальном многоканальном материале.

## Найдено и исправлено

Первый запуск на восьми барабанных дорожках создал WAV, но завершился с
кодом 1: NumPy bool в `source_envelopes.*.crest_ok` не сериализуется в JSON.
На границе манифеста добавлен `bool(...)`. Тип поля остаётся логическим;
обработка аудио не меняется. Два теста воспроизводили ошибку до исправления;
после него 27 тестов source-envelope/pipeline прошли.

## Границы результата

Это execution/repeatability evidence, не доказательство хорошего сведения.
Принятые оператором эталонные миксы и третий независимый мультитрек пока
не определены; данные запрошены. Барабанный материал не выдаётся за полный
концертный состав. Гейт восстановления >=90% на трёх мультитреках не закрыт.
Санитарная обработка сработала на исходниках; правильность удаления найденных
clicks не подтверждена прослушиванием.

Выявлена следующая измеримая проблема: SmartDSP sidecar занимает 209435690
байт для 8 дорожек и 388707378 байт для 16. Это отдельный кандидат для
проверки повторяющихся данных и ограничения стоимости отчётности.

Полный suite запускается после итоговой truth-записи. CP05 остаётся
неперепривязанным с предыдущего коммита; независимое ревью ранее было
недоступно из-за Kimi 403. Успешный полный suite и аппаратный допуск здесь
не заявлены. Пульт не подключался, live-записей не было.
